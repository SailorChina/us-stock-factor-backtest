## 1. 环境准备

### 1.1 Python 与依赖

```bash
python --version          # 需要 3.12+
pip install -r requirements.txt
```

依赖清单：

| 包 | 用途 | 必须 |
|---|---|---|
| pandas | 面板数据、因子计算 | ✅ |
| numpy | 向量化运算 | ✅ |
| matplotlib | 权益曲线图 | 画图才需要 |
| scikit-learn | 部分深度指标实验 | 只在 `_deep_indicators_v11.py` |
| futu-api | 连 OpenD 拉实时行情 | 只有拉取/刷新才需要 |

### 1.2 Futu OpenD（只有需要联网时才要）

回测和信号计算**完全离线可跑**（数据 CSV 已随仓库提供）。只有"刷新到最新行情"才需要 OpenD：

1. 启动 Futu OpenD，登录你的富途账号
2. 确认监听端口为 **11111**（与脚本内配置一致）
3. 验证端口活着：
   ```bash
   python -c "import socket;s=socket.socket();s.settimeout(2);print('OK' if s.connect_ex(('127.0.0.1',11111))==0 else '未启动')"
   ```

脚本还会 import 富途 SDK 的辅助模块（`create_quote_context` / `safe_close`）。
如果你的环境里没有现成的 `common` 模块，把脚本顶部的这行改成你的 futu 工具目录：

```python
sys.path.insert(0, r"C:/Users/sailor/.workbuddy/skills/futuapi/scripts")
```

或者直接用 `futu.OpenQuoteContext` 替换。

### 1.3 OpenD 的三个已知坑（本项目已内置规避）

| 坑 | 现象 | 代码里的处理 |
|---|---|---|
| **日志写入被拒** | 进程**静默退出**、无 traceback，极易误判为 OpenD 故障 | 在 `import futu` **之前**把 `APPDATA` 重定向到临时目录 |
| **线程不退** | 脚本跑完进程不退出 | 建 context 前调 `SysConfig.set_all_thread_daemon(True)` |
| **额度静默耗尽** | 拉不全但不报错，结果是"看起来合理的错答案" | 拉之前查额度、拉之后校验覆盖率，不足则退出码 2 |

## 3. 数据层

### 3.1 数据文件

| 目录 | 内容 | 谁在用 |
|---|---|---|
| `data_kline_long/` | **37 只股票日线**（2018-01-02 ~ 2026-09-11） | 主回测、每日信号 |
| `data_index_long/` | SPY / TLT / GLD / SHY 日线 | 熊市防御专题（v14） |
| `data_kline/` | 早期短周期数据 | v1~v5 旧回测 |

文件名格式：`US_META.csv`（点号替换成下划线）。字段：

```
time_key, open, close, high, low, volume
```

- **复权口径**：前复权（`AuType.QFQ`）。拿它算历史收益率是自洽的；
  但**别拿它当"当时的真实价格"**去看绝对价位。
- **编码**：UTF-8 无 BOM
- **日期格式**：`YYYY-MM-DD`

### 3.2 重新拉取数据

```bash
python _fetch_long.py           # 重拉 37 只股票全段历史（会翻页，约 2~3 分钟）
python _fetch_index_long.py     # 重拉 SPY/TLT/GLD/SHY
python _update_signal.py        # 日常增量刷新（只拉最近 45 天，快）
```

### 3.3 数据层的四个陷阱

| 陷阱 | 为什么危险 | 怎么识别 |
|---|---|---|
| **未完成 bar** | 盘中拉的日线 bar **有价有量**，`volume>0` 检查全部通过，但它是中间价 —— 用来算信号**不会报错，只会悄悄算错** | ① 文件 mtime 换算美东时间是否落在 9:30–16:00 ET；② 末根全池成交量 < 近 20 日中位数 50% |
| **单次请求只返回区间前 N 根** | `request_history_kline(start=504天前, end=今天, max_count=315)` 拿到的是**区间最早**那段，最后一根可能早 45 天 | **取完必须校验最后一根 bar 的日期** |
| **额度分两层** | 除了频率限制（约 60 次/30 秒），还有**额度预算**：每只标的 30 天内只计 1 次，重复请求免费。按账户资产分级 | `ctx.get_history_kl_quota(get_detail=True)` |
| **`ffill` 造出假历史** | 无限向前填充会把「上市前」补成假价格，让次新股混进截面排名 | 用 `ffill(limit=10)` + 上市时长闸门（`MIN_HIST=253`） |

> 规则：**美东收盘（北京次日 04:00）之前不要跑信号**。`_update_signal.py` 会自动检测并拒绝执行。

## 4. 跑回测

### 4.1 主引擎：`_bear_defense_v14.py`

```bash
python _bear_defense_v14.py
```

这是**修复版引擎**，也是所有结论的来源。核心机制：

```
T 日收盘算信号 → T+1 开盘价成交（O[i+1]）
每 21 个交易日调仓一次，Top2 等权满仓
滑点 0.05%，佣金按笔
```

**已验证无前视偏差**：把面板截掉最后 21 根重算，前段信号最大差异 = `0.00e+00`。

输出段落：

| 段 | 内容 |
|---|---|
| `[引擎自检]` | 满仓日闲置现金占比（应 ≈ 0%，> 5% 说明分配有 bug） |
| `Q0` | Top1~Top4 × 两个因子的回测对照 |
| `[诊断]` | 极端收益来源核查（数据异常 vs 少数几期暴涨） |
| 捕获率表 | 各牛熊分段的收益/回撤 |

### 4.2 ⚠️ 佣金口径说明（重要）

`_bear_defense_v14.py` 内部仍使用**早期的佣金近似**：

```python
comm = lambda sh: max(abs(sh) * 0.005, 1.0)      # 0.5%，最低 $1
```

而你实盘是富途的 **$2 / 笔**（买 $2 + 卖 $2，按笔固定、不分股数）。两套口径的差异：

- 长期收益差约 **−900pp**（8.7 年复利）
- **结论方向完全一致**（哪个因子好、Top2 vs Top3 的排序都不变）

要按 $2/笔 复算，用 `_capital_invariance_v22b.py`（它会把引擎源码里的佣金函数替换成 $2/笔 后再跑）：

```bash
python _capital_invariance_v22b.py
```

## 5. 每日实盘流程（SOP）

### 5.1 什么时候跑

| 时间（北京） | 美股状态 | 能否跑 |
|---|---|---|
| 04:00 之后 | 已收盘 | ✅ **推荐**，这是唯一能拿到完整收盘 bar 的时段 |
| 08:00–16:00 | 夜盘 | ❌ 未完成 bar，脚本会拒绝 |
| 16:00–21:30 | 盘前 | ❌ 未完成 bar |
| 21:30–04:00 | 常规盘中 | ❌ 未完成 bar，脚本会拒绝 |

> 夏令时（3 月第二个周日 ~ 11 月第一个周日）：常规时段 = 北京 **21:30** 开盘。
> 冬令时：延后一小时 = **22:30** 开盘。脚本会自动判断，不用手动改。

### 5.2 跑什么

```bash
# 标准流程：刷新行情 + 出清单
python _update_signal.py

# 不想联网（用本地已有数据）
python _update_signal.py --no-fetch
```

### 5.3 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `--no-fetch` | 关 | 不联网，只用本地数据 |
| `--self-test` | — | 跑 26 项断言（含无未来函数、资金无关性） |
| `--capital <USD>` | ¥1万 ÷ 汇率 | 指定本金（美元）。**只影响股数，不影响选股** |
| `--cny <CNY>` | 10000 | 用人民币本金，自动除以汇率 |
| `--fx <rate>` | 6.7092 | 汇率 |
| `--topk <n>` | 2 | 持股数。这是**策略参数**，由信号决定，不要因为钱少而改小 |
| `--strategy <name>` | Vortex | 可选 `Vortex` / `动量-1月反转` / `动量12-1` |
| `--positions META:1,BE:2` | 读 `portfolio.json` | 告知实际持仓，算真实盈亏与换仓指令 |
| `--bought META:1.15@648.03,BE:2.70@275.75` | — | 记录成交，写入 `portfolio.json` 供下次读取 |

退出码：`0` 正常 / `2` 数据不可靠（**不要据此下单**）。

### 5.4 输出解读

```
[1] 刷新行情        拉取 37 只 + VOO，报告覆盖率（< 95% 会告警）
[2] 数据体检        未完成 bar / 覆盖度 / 极端跳变 / 僵尸票 / 面板空洞
[3] 调仓日历        今天是不是调仓日；不是的话给下次调仓日 + 执行日 + 开盘时间
[4] 下单清单        选票 + 每只目标金额 + 整股/碎股股数 + 闲置现金 + 佣金
[5] 换仓指令        最小换手的逐笔动作（买卖/持有/清仓）
[6] 执行须知        T+1 结算、订单类型、闲置现金、汇率提示
```

`[4]` 段示例：

```
[4] 下单清单  净值 $1,490  汇率 6.7092
  策略 Vortex Top2: META, BE
  （选股仅由因子得分排序决定, 与本金/价格/佣金无关; 本金只影响下面每只买多少股）

  标的               现价       目标金额     整股       整股金额       碎股股数        建议
  META    $    648.03$       745      1$    648.03     1.1500      整股OK
  BE      $    275.75$       745      2$    551.50     2.7026      整股OK

  整股投入 $1,200 (占净值 80%), 闲置 $291
  佣金 卖 0x$2 + 买 2x$2 = $4 (占净值 0.27%)
  碎股方案: 每只按金额 $745 买入, 份额 META 1.1500股, BE 2.7026股
```

- **碎股方案**是首选：富途支持按金额下单，可以让资金利用率接近 100%
- 整股方案会出现闲置现金（上例 20%），小资金下这个损耗不可忽略
- "碎股股数"列就是**建议下单的份额**

### 5.5 下单

1. **时点**：执行日北京时间 **21:30**（夏令时）/ 22:30（冬令时）**开盘**
2. **不要用夜盘/盘前**：流动性薄、价差大，与回测假设（开盘价成交）不符
3. **订单类型**：碎股通常只支持市价单；整股可用开盘价限价
4. **现金账户 T+1**：卖出的钱要 T+1 才结算。同日"先卖后买"可能触发
   Good Faith Violation → 现金账户建议**先买后卖**，或把买卖拆到两天
5. **成交后记录**（让下次能自动算盈亏）：
   ```bash
   python _update_signal.py --no-fetch --bought META:1.15@648.03,BE:2.70@275.75
   ```

### 5.6 换仓的最小换手逻辑

`[5]` 段只对偏离超过阈值（`max($25, 目标金额×12%)`）的仓位动手：

```
动作        含义
持有        偏离小，不动（省 $4 佣金）
买入/卖出   调整到目标金额
清仓        掉出 TopK 的持仓
```

> 无脑全卖全买 = TopK×2×$2；最小换手通常只动 0~1 只，能省下一半以上佣金。

## 6. 自检与验证

### 6.1 全链路自检

```bash
python _update_signal.py --self-test
```

26 项断言，覆盖：

| 类别 | 断言举例 |
|---|---|
| 夏令时 | 边界日期 3/8 起、11/1 止 |
| 交易日历 | 劳动节休市、周末非交易日、`next_trading_day(9/11)=9/14` |
| 时区 | 北京 9/12 03:00 → 美东 9/11 15:00 |
| 盘中 bar 检测 | 同一根 bar 在 03:00 判为未完成、11:00 判为已完成 |
| 数据 | 无重复日期、面板列数 = 标的数、OHLC 无 `high<low` |
| **无未来函数** | 截断后前段信号最大差异 = 0 |
| 调仓序列稳定性 | 追加数据后历史调仓日不漂移 |
| 佣金 | Top2 换仓 = $8 |
| **资金无关性** | 选股源码不含资金变量 / 选票对 $0.01~$1e12 本金不变 / 签名无资金参数 |

### 6.2 资金无关性验证

验证「**选股信号不受回测金额影响**」这条原则：

```bash
python _capital_invariance_v22b.py      # 推荐：修正版，2 分钟
```

三段验证：

| 段 | 方法 | 结论 |
|---|---|---|
| A | `subprocess` 直接跑生产脚本，跨 6 档本金（$1 → $1000万） | 选票完全相同 |
| B | 源码级复用回测引擎，跨 9 档本金比对**每个调仓日的实际持仓集合** | ≥$300 时 92/92 个调仓日 0 差异，**真·换股 0 次** |
| C | 零成本剥离出纯信号能力，看哪档 TopK 最优 | Vortex k=2，与本金无关 |

> 脚本会覆写 `signal_snapshot.json`，且**已内置备份还原**，不会污染真实信号文件。

## 7. 移植到富途牛牛量化平台

`strategy_momentum_stop_v5.py` 是给**牛牛 App 内置量化平台**用的（在线 Web 环境，有独立的内置函数体系）。

| | OpenAPI SDK | 牛牛量化平台 |
|---|---|---|
| 运行环境 | 本地 Python 脚本 | 在线 Web |
| 连接方式 | 连本地 OpenD（端口 11111） | 平台托管 |
| 函数体系 | `futu` 包 | 平台内置 `declare_*` / `show_variable` 等 |
| 本项目的对应文件 | `_update_signal.py` 等 | `strategy_momentum_stop_v5.py` |

**移植注意**：
1. 平台内置函数名请在平台右上角「量化使用手册」里核对
2. 策略参数用 `show_variable()` 暴露，方便在界面上调
3. 回测口径差异：本仓库的结论基于「T+1 开盘价成交 + $2/笔」，平台上跑出来的数字会有差异，**不要拿平台的数字反推本仓库的结论**

## 8. 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 脚本跑到一半**静默退出**，无报错 | futu SDK 写日志被拒 | 已内置 `APPDATA` 重定向；若仍失败，手动设置可写目录 |
| 脚本跑完**不退出** | futu 线程未设为 daemon | 确保 `SysConfig.set_all_thread_daemon(True)` 在建 context **之前**调用 |
| `[XX] 严重: 最后一根是未完成 bar` | 在美股盘中跑的 | 等北京次日 04:00 后重跑 |
| 拉取只拿到前几十只就没数据了 | **频率限制**（约 60 次/30 秒）超限，**立即失败且不抛异常** | 已内置节流 + 冷却重试；批量取数前先查额度 |
| 额度显示很小却拉不动 | 误判：已拉过的标的 30 天内**重复请求免费** | 别写 `remaining < n 就拒绝` 的逻辑 |
| 某只票"暴涨 50%" | 可能是 `np.where` 行列索引写反，也可能是真实财报跳空 | 用 `_probe_quality.py` 核对 |
| `float(dict)` 静默吞异常 | `portfolio.json` 结构变了 | 检查文件格式，见下方示例 |
| `--positions` 报"不在标的池的代码" | 代码拼错 | 拼错会让市值按 0 计 → 净值被低估 → 目标股数全错，脚本会拦下 |
| git 报 `error adding trust anchors from file` | `.gitconfig` 里 `http.sslCAInfo` 指向不存在的路径 | 改成实际的 `ca-bundle.crt`，或设 `git config --global http.sslBackend schannel` |

`portfolio.json` 格式：

```json
{
  "as_of": "2026-09-14",
  "shares": {
    "META": { "shares": 1.15, "price": 648.03 },
    "BE":   { "shares": 2.70, "price": 275.75 }
  }
}
```

## 9. 速查表

### 每天做什么

```bash
# 收盘后（北京 04:00 之后）
python _update_signal.py

# 有成交就记一笔
python _update_signal.py --no-fetch --bought META:1.15@648.03

# 定期体检
python _update_signal.py --self-test
```

### 关键常量

| 常量 | 值 | 位置 |
|---|---|---|
| 调仓周期 | 21 个交易日 | `_update_signal.py: REBAL` |
| 预热根数 | 252 | `START` |
| 佣金 | $2/笔 | `COMM` |
| 参与排名最少历史 | 253 根 | `MIN_HIST` |
| 面板最大前向填充 | 10 根 | `MAX_FFILL` |
| 数据陈旧告警 | 4 个日历日 | `STALE_DAYS` |
| 滑点 | 0.05% | `_bear_defense_v14.py: backtest(slip=)` |

### 时段对照（北京 ↔ 美东）
